# Tools hub e2e (Link 0.3)

`tools/e2e.py` verifies plan §17.2 (ARCADE_TOOLS_PLAN.md) with the real
apps, real AppImages and the actual Tools core. Every lifecycle runs in an
isolated session: a private D-Bus bus (`dbus-run-session`), Xvfb, a throwaway
keyring, and temporary `HOME`, `XDG_*`, `ARCADE_HOME` and per-app homes. No
Wayland/Hyprland variables are passed in. Nothing reads or writes the real
profile.

Link v0.3.0 is pinned. This harness changes no library or protocol code.

## Running it

Prerequisites are `Xvfb`, `dbus-run-session` and `xdotool`. The trayhost
checks also need `python3-dbus` and `python3-gi`. The runner builds the
`arcade-link` debug CLI itself, with `CARGO_BUILD_JOBS=3`.

```sh
# A group by name, or several groups (each runs in a new isolated session)
python3 tools/e2e.py tools-hub
python3 tools/e2e.py --only presence,install,trayhost,tools-hub

# Any command inside an isolated session (Xvfb + private bus + temp homes)
python3 tools/e2e.py run -- arcade-link ls
python3 tools/e2e.py run -- python3 tools/e2e.py --only presence,install,trayhost,tools-hub

# Real fleet, one group. --allow-skips accepts *reported* skips; failures still fail.
python3 tools/e2e.py run -- python3 tools/e2e.py --real-apps --allow-skips --only tools-hub
python3 tools/e2e.py run -- python3 tools/e2e.py --real-apps --only shortcuts --check arcade_find_global_shortcut_round_trip
```

Without `--real-apps`, `install`, `trayhost`, `shortcuts` and `tools-hub`
run the deterministic Link scaffold: mock peers from `fixtures/*.json`,
Link's watchers and install harness. This mode is the PR gate and needs no
sibling checkout.

With `--real-apps`, the group checks come from `tools/e2e_checks/real_hub.py`.
There are two ways to choose which builds they run:

1. **CI artifacts (recommended).** Download the latest green
   `arcade/tools-hub` Linux AppImage of each app, plus its sources at that
   exact commit. Use a new, empty directory under `/tmp`, and treat the
   downloads as untrusted:

   ```sh
   python3 tools/e2e_artifacts.py --sources --output /tmp/arcade-fleet-$(date +%m%d)
   export ARCADE_E2E_ARTIFACTS=/tmp/arcade-fleet-MMDD/fleet.json
   export ARCADE_TOOLS_REPO=...   # Tools publishes no branch AppImage; see below
   ```

   The fetcher checks that each file is an ELF AppImage. It records the run,
   commit and SHA-256 in `<AppImage>.provenance.json`, and writes `fleet.json`.
   Any app it couldn't fetch gets a `reason` there. The harness re-hashes each
   package before use.
   Each `gh run download` gets 300 s and one retry; if both fail, that app is
   skipped as `artifact download failed`. If you rerun into the same
   directory, verified packages from the same run and clones at the selected
   commit are reused. Set `TMPDIR` to a disk directory if `/tmp` is a small
   tmpfs, because `gh` stages each ZIP there. The shortcut checks also read
   the catalog's sheets (`ARCADE_CATALOG_REPO`, a checkout of
   `qa-p1/Arcade-catalog`).
2. **Local worktrees.** Source `tools/hub-env.sh` (in the task shell only) to
   point `ARCADE_<APP>_REPO` at the `-wt-hub` worktrees, and build them.
   `ARCADE_<APP>_BIN` and `ARCADE_<APP>_APPIMAGE` override single files.

Isolated sessions inherit `CARGO_HOME` and `RUSTUP_HOME`, so
`python3 tools/e2e.py run -- cargo …` uses the shared registry and toolchain
instead of rebuilding under the temporary `HOME`.

Write a JSON report per group with `ARCADE_E2E_REPORT_DIR=<dir>`. Turn the
reports into the group × app table with
`python3 tools/e2e_coverage.py <dir> [--fleet fleet.json]`.

### Result states

| State | Meaning | Exit code |
|---|---|---|
| `PASS` | the assertion ran and held | 0 |
| `SKIP` | a prerequisite is unavailable (no green artifact, stale or missing build, a pre-hub checkout); the reason is printed and stored | 1, or 0 with `--allow-skips` |
| `XFAIL` | a documented product bug outside Link, matched by its exact symptom text | 0 |
| `XPASS` | a check marked as a known bug passed; remove the stale note | 1 |
| `FAIL` | anything else, including a checksum mismatch or a different error from a known-bug check | 1 |

Only `SkipCheck` produces a skip. An `AssertionError` is never turned into a
skip because of its message text (`tools/test_e2e_hub.py` tests this).

### CI

`.github/workflows/e2e.yml`:

- **`contract`** (every push/PR, deterministic): the scaffold groups
  `presence,install,trayhost,tools-hub`, then the real-app `install` group with
  `--allow-skips`. PRs never download mutable sibling builds, so that second
  step lists all eight apps as `SKIP`. The coverage table goes into the job
  summary.
- **`real-fleet`** (opt-in: nightly at 02:17 UTC, `workflow_dispatch` with
  `real_apps: true`, or a PR carrying the `e2e-real-fleet` label): a
  `install`/`trayhost`/`tools-hub`/`shortcuts` matrix. Each job runs
  `e2e_artifacts.py --sources` and clones the public catalog. It builds Tools
  natively at its green `arcade/tools-hub` commit, because Tools' branch CI
  uploads no Linux AppImage. Then it runs the group against the real fleet.
  Known product bugs (none open) would show as XFAIL in this matrix only.

`tools/test_e2e_hub.py` runs in the regular `CI` workflow
(`python3 -m unittest discover -s tools`). It checks that all eight apps are
covered, that skips are never counted as passes, the XFAIL/XPASS rules,
non-JSON settings exports and the coverage table.

## Groups and what they assert

The per-app table is the `FLEET` dict in `tools/e2e.py`. Each entry holds the
protocol id, CLI name, repository, CI artifact name pattern, binary, package
globs and tray expectations. Per-app checks are generated from it, so each
app gets its own named result (`arcade_<app>_<case>`) and its own disposable
profile.

### `install`: 16 real checks (8 apps × 2)

| Check | Asserts |
|---|---|
| `<app>_appimage_install_update_repair_uninstall_reexec` | Starts from the app's AppImage in a temp `~/Downloads`. `--integration-status` shows no receipt. `--install --silent --no-launch` writes a 0755 AppImage, the desktop entry, icons, the CLI symlink (named after the app) and a 0600 receipt, all inside the temp root. A reinstall over a `0.0.1` receipt keeps a byte-identical `previous`. Repair after moving the file rewrites the launcher and CLI to the new path. Uninstall removes every owned file. `--install --silent` without `--no-launch` starts the installed copy and exits 0 (so the download's mount goes away); the app's own registry manifest proves the path. |
| `<app>_development_install_suppression` | A native development build publishes `install: "dev"` (the seven apps), writes no receipt and shows no "Install Arcade" window, even with `ARCADE_NO_INSTALL_PROMPT` unset. |

Scaffold check (the default mode): `install_update_repair_and_uninstall_use_only_a_temporary_home` (Link's install harness).

### `trayhost`: 27 real checks

| Check | Asserts |
|---|---|
| `real_apps_hand_back_within_one_second_after_tools_sigkill` | Seven real apps, then Tools: all report `status.tray: hosted`. After a `SIGKILL` to Tools (this run's PID only), each app reports `own` within 1 s, observed over preconnected sockets. |
| `tools_first_restart_and_clean_quit_preserve_real_app_trays` | Tools first, then the apps become `hosted`. `app.restart` → no app is ever sampled as `own` during the restart window (no flash). A clean quit hands every app back within 1 s. |
| `real_tools_per_app_opt_out_keeps_the_apps_own_icon` | Tools excludes all seven apps; each keeps `own`, and Tools' manifest publishes the exclusion list. |
| `hosted_real_apps_remove_their_status_notifier_items` | A real `StatusNotifierWatcher` sees one item per app when `own`, none from any app while hosted, and all of them again after Tools is SIGKILLed. Passive items stay visible in Caelestia/Waybar, so `app.status` alone isn't enough. |
| `disabling_link_in_find_keeps_its_own_icon` | Find with Link disabled: native `--status` reports `own` while Tools runs, and there's no Link endpoint. |
| `<app>_standalone_status_notifier_item` (8) | Each app alone (Tools included) registers exactly one SNI item, and the seven apps report `own`. |
| `<app>_hosting_crash_opt_out` (7) | Per app: own SNI → hosted, with the app's SNI removed and Tools' host icon present. SIGKILL hands back to `own` within 1 s and the SNI returns. Per-app opt-out keeps the app's own icon. |
| `<app>_link_disabled_own_icon` (7) | Turns Link off through each app's native settings store (SQLite, TOML, JSON or shared_preferences). The app shows its own SNI while Tools runs, publishes `linkEnabled: false` and has no live endpoint. |

Scaffold check: `seven_watchers_hand_back_after_crash_and_restart_without_flash`.

### `tools-hub`: 43 real checks

| Check | Asserts |
|---|---|
| `loopback_catalog_is_loaded_by_the_real_tools_core` | The actual Tools core (the `real_app_driver.rs` adapter, built from the selected Tools sources) fetches a catalog from a loopback HTTP server. |
| `loopback_catalog_bundle_install_real_packages` | A seven-app bundle is installed through each app's own installer. The receipts say `managedBy: tools` and each app serves Link. |
| `<app>_bundle_install` (7) | The same flow for each app on its own. |
| `<app>_update_rollback_incompatible_hold` (7) | Real AppImage bytes are updated and then rolled back to the identical hash. A `protocol: [2]` release is reported held/incompatible and refused, and the bytes don't change. |
| `<app>_manual_appimage_adoption` (8) | A manual AppImage registered from its own `--arcade-manifest` lists as `manual`; `adopt` creates a Tools-managed receipt. |
| `tools_self_update_stages_and_applies_a_real_appimage` | Tools stages its own update, quits, and a helper applies it and restarts it. An incompatible self-update is refused. |
| `diagnostics_zip_contains_real_app_state_and_redacts_secrets`, `<app>_diagnostics_redaction` (8) | The diagnostics ZIP includes each manifest and declared logs. Tokens, passwords, manifest secrets and the home path are redacted. |
| `portable_backup_restores_real_app_settings_in_a_second_arcade_home`, `<app>_portable_settings_restore` (7) | Export → Tools portable ZIP (no device identity or private key) → restore in a second, independent `ARCADE_HOME`. The re-export must equal the original. Exports aren't JSON-only: Shelf's binary container is compared by manifest (minus `createdAt`) plus a payload hash. |
| `tools_preferences_restore_without_any_app_binary` | Link/update policy plus a non-default channel and auto-update survive the round trip with no app installed. |

Scaffold check: `hub_contract_against_mock_peers`.

## Known product bugs

None open. The three backup bugs below were found by this matrix and **fixed in
Arcade Tools 0.2.0** ([qa-p1/Arcade-tools#4](https://github.com/qa-p1/Arcade-tools/pull/4), `cf8f0c5`).
Tools now accepts boolean settings whose names mention secrets, attributes an
export without `owner` to the app it asked, and stores non-JSON exports
byte-for-byte with a sha256. `BACKUP_BUGS` in `tools/e2e_checks/real_hub.py` is
empty, so every app's settings must round-trip. A new known bug goes there:
it shows as `XFAIL` only when the failure contains its documented symptom, and
any other error, or a pass (`XPASS`), fails the run so the note gets removed.

The real-fleet matrix downloads each app's newest green `main` build
(`ARCADE_E2E_BRANCH` selects another branch).

History of the fixed bugs:

All three were confirmed in CI ([run 38606704365](https://github.com/qa-p1/Arcade-Link/actions/runs/38606704365))
and against the sources: Tools `a786164`, Lens `05f4f27`, Wheel `3ccd7f3`,
Shelf `1b8bedf`. Repro (CI artifacts in an isolated session):

```sh
python3 tools/e2e_artifacts.py --sources --output /tmp/arcade-fleet-new
ARCADE_E2E_ARTIFACTS=/tmp/arcade-fleet-new/fleet.json ARCADE_TOOLS_REPO=<Tools arcade/tools-hub checkout> \
  python3 tools/e2e.py run -- python3 tools/e2e.py --real-apps --only tools-hub \
  --check arcade_lens_portable_settings_restore,arcade_wheel_portable_settings_restore,arcade_shelf_portable_settings_restore
```

| App | Symptom (Tools `backup` → `notIncluded`) | Cause |
|---|---|---|
| Lens | `arcade.lens`: "The app settings contained excluded data or exceeded backup limits." | Lens' export (`arcade-lens-settings.json`, 454 bytes) contains the setting key `privacy.guard_secrets`. Tools `src/portable_backup.rs` `contains_excluded_data()` rejects any key whose normalized name *contains* `secret`, so a boolean privacy toggle blocks the whole export. Fix in Tools (match whole words or an allowlist) or rename the Lens key. |
| Wheel | same message | Wheel's `app.settings.export` reply (`src/link/WheelLink.cpp`) returns `{"type": "file/any", "path": …}` with no `owner`. Tools `handoff_source()` requires `owner == "arcade.wheel"` and treats the output as invalid. Fix in Wheel (add `"owner": "arcade.wheel"`). |
| Shelf | same message | Shelf exports a binary `ARCADE-SHELF-PORTABLE` container (magic, big-endian u64 manifest length, JSON manifest, payloads). Tools `portable_backup.rs` parses every settings export as JSON (`serde_json::from_slice::<Value>`) and rejects anything else. Fix in Tools (accept owned binary exports) or in Shelf (JSON export). The harness used to assume JSON-only exports too; `export_snapshot()` now compares Shelf's container by manifest (minus `createdAt`) plus a payload hash. |

The fleet-wide `portable_backup_restores_real_app_settings_in_a_second_arcade_home`
is XFAIL for the same three apps. The other four apps' settings and the Tools
preferences still have to round-trip before the expected failure is raised.

Documentation inconsistency (no check fails on it): Box
`docs/user/getting-started.md` says the installed command is **arcade-box**, but
the installer links the desktop app as `arcade-desktop`
(`apps/desktop/src-tauri/src/installer.rs`, `CLI_NAME`). The harness records
Box's CLI name as `arcade-desktop`.

## §17.3 real-desktop checklist (owner, by hand)

These need the owner's real Hyprland/Caelestia session and can't be automated
under Xvfb. Record each result in plan §21. Don't use `hyprctl dispatch
closewindow class:…`: it closes the focused window. Use `address:` only.

1. **Install from Downloads.** For each released AppImage:
   - [ ] Save it to `~/Downloads`, run it, and install through the dialog.
   - [ ] It appears in the Caelestia launcher (Super).
   - [ ] Its CLI works from fish (e.g. `arcade-find --version`).
   - [ ] Autostart points into `~/Applications/Arcade`.
2. **Tools tray.**
   - [ ] Exactly one Arcade icon. The app icons are hidden.
   - [ ] Each app submenu's Open, Settings, Restart, Quit and extras work.
   - [ ] Quit Tools: every app icon returns.
   - [ ] Start Tools again, then `kill -9 <Tools pid>`: every app icon returns within about 1 s.
3. **Cheat-sheet overlay.** Press `Super+/` over each of these, and check that it opens on top and closes cleanly:
   - [ ] Firefox
   - [ ] T3 Code
   - [ ] a terminal
   - [ ] Find
   - [ ] an unknown app

   - [ ] The Hyprland binds are labeled from the real Lua config.
4. **Rebind from Tools.**
   - [ ] Change Find's global shortcut in Tools.
   - [ ] `hyprctl binds -j` (read-only) shows the new runtime bind.
   - [ ] Find's own settings show the new binding.
   - [ ] Restore the original binding.
5. **Real update.**
   - [ ] Update one app from a real release (on the nightly channel).
   - [ ] It launches.
   - [ ] Roll back, and the previous version runs again.
6. **Owner first-install run.**
   - [ ] Tools first, then apps from Tools.
   - [ ] Separately: one app installed alone from its AppImage, without Tools, keeps its own tray icon and settings.
